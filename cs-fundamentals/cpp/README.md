## 笔记

#### 1. 指针、引用与 const

- 指针和引用的区别

  指针是变量的地址，引用是变量的别名。指针可以通过解引用来改变变量的值，引用则可以直接改变变量的值

- 常量指针和指针常量的区别

  常量指针是指向常量的指针，定义格式为：const int *p，不能通过解引用来修改指向变量的值
  指针常量是不能改变指向的指针，定义格式为：int * const p，能通过解引用来改变指向对象的值，但是不能改变指向的对象

- 类的成员函数后面加const
  类的成员函数后面加上const，表示该函数不能改变成员变量的值。

### 2. STL容器

### 3. `char* s` 与 `char s[]` 的区别

**结论：** `char s[] = "hello"` 是数组，内容是**可修改的拷贝**；`char* s = "hello"` 是指针，指向只读区 `.rodata` 里的字符串字面量。

**原理：**

- 数组：编译器在栈（局部）或静态区分配 6 字节，把 `"hello\0"` 拷贝进去；`s[0]` 可改，`sizeof(s)` = 6。
- 指针：字面量类型是 `const char[N]`，存放在只读数据段；`s` 只是 8 字节指针，`s[0]` 修改是未定义行为（通常段错误），`sizeof(s)` = 8。

**追问 / 易错点：**

- C++11 起 `char* s = "hello"` 编译报错（const 不能隐式转非 const），必须写 `const char*`。
- 数组名是常量，不能 `s = ...` 重新赋值；指针可以。
- `&s`：数组是 `char(*)[N]`（数组指针），指针是 `char**`。

### 4. map 与 unordered_map 插入/删除后的迭代器失效

**结论：** 两者都是节点式容器。`map` 插入/删除都不会失效其它迭代器（只失效被删者）；`unordered_map` 删除只失效被删者，但插入时若发生 rehash 会失效**所有**迭代器（引用/指针仍有效）。

**原理：**

- `map`（红黑树）：insert/erase 只调整指针链接，不搬动已有节点 → 其它迭代器/引用/指针全部有效。
- `unordered_map`（哈希表）：erase 不触发 rehash，其它迭代器有效；insert 在负载因子超阈值时 rehash，桶被重排 → 所有迭代器失效，但元素节点未移动 → 引用/指针仍有效。

**追问 / 易错点：**

- 别记成「unordered_map 插入一定全失效」——只有 rehash 时才失效。
- 即便 rehash，`&element`（引用/指针）仍有效，这是它与 `vector` 扩容（元素整体搬移）的关键区别。

### 5. 堆（二叉堆 / priority_queue）插入删除时间复杂度

**结论：** 插入 O(log n)，删除堆顶 O(log n)，建堆 O(n)，取堆顶 O(1)。

**原理：**

- 插入：元素放末尾，上滤（sift-up），最多树高 log n 次比较/交换。
- 删除堆顶：堆顶与末尾交换、弹出，再对新堆顶下滤（sift-down）。
- 建堆：自底向上 heapify 为 O(n)；逐个插入为 O(n log n)。

**追问 / 易错点：**

- 删任意元素：查找 O(n)（除非维护「值 → 下标」映射），删除动作本身 O(log n)。
- 建堆 O(n) 是高频追问，容易误答成 O(n log n)。

### 6. 浮点数比较 `0.05 + 0.01 == 0.06`

**结论：** false。

**原理：**

- 0.05 / 0.01 / 0.06 在二进制下都是无限循环小数，double 无法精确表示。
- 实际值：`0.05 + 0.01 ≈ 0.060000000000000005`，`0.06 ≈ 0.059999999999999998`，二者不等。

**追问 / 易错点：**

- 正确比较用误差容限：`fabs(a - b) < 1e-9`，或相对误差 `fabs(a-b) < eps * max(fabs(a), fabs(b))`。
- 只有分母为 2 的幂的分数能被 IEEE 754 精确表示；0.05 = 1/20 含因子 5，故不精确。
- float 约 6~7 位有效数字，double 约 15~16 位。

### 7. `*(char*)` 类型转换 / 空指针解引用

**结论：** 取决于题目写法——`*(char*)0` 是空指针解引用（UB，通常段错误）；`*(char*)&x` 是经 `char*` 查看对象首字节（判断大小端，合法）。

**原理：**

- `char*` / `unsigned char*` 是 strict aliasing 规则的特例，唯一可以合法别名任意类型的指针。
- 解引用空指针 / 越界读写都是未定义行为，实际通常崩溃。

**追问 / 易错点：**

- 用 `char*` 强转非 char 指针再解引用可能违反 strict aliasing，属 UB。
- 判断大小端：`int x = 1; *(char*)&x == 1` 为小端。
