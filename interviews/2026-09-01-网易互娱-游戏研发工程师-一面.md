## 问题与回答

### 1. `char* s` 与 `char s[]` 的区别

**我的回答：** 未完整答出。

**更好的回答：**
前者是指向字符串字面量的指针，后者是数组（存了一份拷贝）。

- `char s[] = "hello"`：编译器在栈上分配 6 字节，把 `"hello\0"` 拷贝进去，内容可改，`sizeof(s)` = 6。
- `char* s = "hello"`：字面量类型是 `const char[N]`，存放在只读区 `.rodata`，`s` 只是 8 字节指针，`s[0]` 修改是未定义行为（通常段错误），`sizeof(s)` = 8。
- C++11 起 `char* s = "hello"` 编译报错（const 不能隐式转非 const），必须写 `const char*`。

**暴露的问题：** C 语言指针 vs 数组基础不扎实。

### 2. 堆插入/删除的时间复杂度

**我的回答：** 未完整答出。

**更好的回答：** 插入 O(log n)、删除堆顶 O(log n)、建堆 O(n)、取堆顶 O(1)。
插入是末尾 + 上滤，删除堆顶是交换末尾 + 下滤；建堆自底向上 heapify 是 O(n)，逐个插入才是 O(n log n)。

**暴露的问题：** 数据结构基础复杂度不熟，尤其建堆 O(n) 易误答。

### 3. map 与 unordered_map 插入/删除后迭代器是否失效

**我的回答：** 未完整答出。

**更好的回答：** 两者都是节点式容器。

- `map`（红黑树）：插入/删除都不失效其它迭代器，只失效被删的那个。
- `unordered_map`（哈希表）：erase 只失效被删者；insert 在 rehash 时所有迭代器失效，但引用/指针仍有效（节点未移动）。

**暴露的问题：** STL 迭代器失效规则记忆模糊，没抓住「rehash」这个关键点。

### 4. `*(char*)`（类型转换相关）

**我的回答：** 未完整答出。

**更好的回答：** 视具体写法而定：`*(char*)0` 是空指针解引用（UB，通常段错误）；`*(char*)&x` 是经 `char*` 查看对象首字节（判断大小端，合法，`char*` 是 strict aliasing 的特例）。

**暴露的问题：** 指针强转与 strict aliasing 概念不清（此题回忆不完整，需补全原题）。

### 5. `0.05 + 0.01 == 0.06` 是否为 true

**我的回答：** 未完整答出。

**更好的回答：** false。0.05 / 0.01 / 0.06 在二进制下都是无限循环小数，double 无法精确表示，`0.05 + 0.01 ≈ 0.060000000000000005`，`0.06 ≈ 0.059999999999999998`，二者不等。正确比较用误差容限 `fabs(a - b) < 1e-9`。

**暴露的问题：** 浮点表示与比较规则不熟。

### 6. TCP 服务端一直停留在 CLOSE_WAIT 大概率因为什么

**我的回答：** 未完整答出。

**更好的回答：** 服务端应用层没有调用 `close()` / `shutdown()`。CLOSE_WAIT 是被动关闭方收到对端 FIN、回 ACK 后进入的状态，若应用收到 EOF（read 返回 0）后不关 socket，就永远停在 CLOSE_WAIT，连接泄漏最终耗尽文件描述符。

**暴露的问题：** TCP 挥手状态机与故障定位不熟，易与 TIME_WAIT 混淆。
